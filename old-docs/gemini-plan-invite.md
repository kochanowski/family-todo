# HousePulse CloudKit Sharing Architecture Plan

This document provides a deep architectural review of the CloudKit Sharing (`CKShare`) implementation for HousePulse, answering specific questions regarding zone creation, link generation, and share acceptance, followed by a bulletproof step-by-step guide.

## 1. CKShare & Zone Creation Sequence

### What is the exact sequence of operations?
To create a shared zone, save a root record, and generate a valid `CKShare`, the sequence **must** be strictly ordered due to CloudKit's server requirements:
1. **Create the Custom Zone**: Initialize a `CKRecordZone` with a custom ID.
2. **Save the Custom Zone**: Save this zone to the `privateCloudDatabase` using `CKModifyRecordZonesOperation`. **You must wait for this operation to succeed on the server before proceeding.**
3. **Create the Root Record**: Create your `Household` `CKRecord`, explicitly assigning its `recordID` to the custom zone you just created.
4. **Create the CKShare**: Initialize `CKShare(rootRecord: householdRecord)`. Assign `share[CKShare.SystemFieldKey.title]`.
5. **Save Both Atomically**: Use a `CKModifyRecordsOperation` to save **both** the `householdRecord` and the `CKShare` in the exact same transaction.

### Should the zone be saved before the record and share are created?
**Yes.** You cannot save a record to a custom zone that does not exist on the server yet. While CloudKit sometimes batches zone creations and record modifications successfully, the most bulletproof approach is to ensure the zone modification operation completely finishes before attempting to save the record or the share.

### How should CKModifyRecordsOperation be configured?
Pass both the root record and the share into the same operation:
```swift
let modifyOperation = CKModifyRecordsOperation(
    recordsToSave: [householdRecord, share],
    recordIDsToDelete: nil
)
modifyOperation.savePolicy = .ifServerRecordUnchanged // or .changedKeys
modifyOperation.qualityOfService = .userInitiated
```
*Why?* Because when you create a `CKShare`, the server automatically modifies the root record to include a reference to the newly created share in its `share` property. Saving them together ensures atomic consistency.

### Common reasons for "Failed to create share"
1. **Submitting to Default Zone**: `CKShare` cannot be used in the `_defaultZone`. The `recordID` of the root record must point to a custom `CKRecordZone.ID`.
2. **Race Conditions**: Attempting to save the `CKShare` before the custom `CKRecordZone` has been fully flushed to the CloudKit servers.
3. **Record Change Tag Conflict**: If you fetch the `Household`, modify it, and try to save the share, but another device modified the Household in the meantime, it results in a `.serverRecordChanged` error.
4. **Partial Saves**: Saving the root record first, then saving the `CKShare` in a separate operation.

## 2. QR Code & Link Generation

### Should the QR code/Link encode the native CKShare.URL directly?
While the native `CKShare.URL` (e.g., `https://www.icloud.com/share/...`) works, using it directly forces the user into Apple's native flow (which opens Safari, then kicks back to the app via `userDidAcceptCloudKitShareWith:`).

For a true custom onboarding experience with QR codes, **you should encode a custom Universal Link** (e.g., `https://housepulse.app/invite?shareURL=<base64_encoded_ckshare_url>`).

### Safest way to pass the CKShare metadata
You cannot encode `CKShare.Metadata` into a QR code; it is too large and dynamic.
You must pass the `URL` generated by the `CKShare` via your Universal Link. Once your app intercepts the Universal Link, you securely decode the `shareURL` parameter and fetch the metadata live from Apple's servers using:
```swift
let metadata = try await container.shareMetadata(for: decodedShareURL)
```

## 3. Intercepting and Accepting the Share

### How to systematically accept without the native iOS Messages/Mail flow
By intercepting your custom Universal Link within the app (`onOpenURL` in SwiftUI or `scene(_:continue:)` in AppDelegate), you extract the underlying iCloud URL. You then fetch the `CKShare.Metadata`.

Once you have the metadata, you present your **custom HousePulse UI** (e.g., "You've been invited to 'The Smiths' Household. Join?").

When the user taps "Join", you programmatically accept the share using `CKAcceptSharesOperation`:
```swift
let acceptOperation = CKAcceptSharesOperation(shareMetadatas: [metadata])
acceptOperation.qualityOfService = .userInitiated
// handle completion block
```

### UICloudSharingController vs CKAcceptSharesOperation
- **`UICloudSharingController`**:
  - *Pros:* Handles all edge cases gracefully (Apple ID sign-in prompts, permissions, stop sharing UI).
  - *Cons:* Rigid UI. Forces Apple's native presentation style. Cannot easily be embedded into a custom onboarding flow cleanly.
- **`CKAcceptSharesOperation`**:
  - *Pros:* 100% custom UI. You design the invitation screen. Perfect for a QR-code driven guest flow.
  - *Cons:* You must manually handle errors, specifically the `.notAuthenticated` error if the user isn't signed into their Apple ID.

**Recommendation:** Use `CKAcceptSharesOperation` for the "Join via Link/QR" flow to preserve your UX, and fallback to `UICloudSharingController` purely for the "Manage Share" screen of the Household owner.

### Deferring Acceptance if the user is a "Guest" (Unauthenticated)
If `fetchShareMetadata` throws `.notAuthenticated`, the user is not signed into iCloud.
1. Catch the `.notAuthenticated` error.
2. Save the `decodedShareURL` to `UserDefaults` or an in-memory `AppState`.
3. Present an onboarding screen: "HousePulse requires an iCloud account to join shared households. Please sign in via Settings."
4. Provide a button that links to iOS Settings.
5. Listen for `CKAccountChanged` notifications or check status on app foreground. Once `accountStatus == .available`, retrieve the cached `shareURL` and automatically resume the `fetchShareMetadata` -> `CKAcceptSharesOperation` flow.

## Bulletproof Implementation Guide

### Step 1: Fix Share Creation Atomicity
In `CloudKitManager.swift`, strictly enforce the zone -> record -> share pipeline:
```swift
// 1. Ensure Zone
let zoneID = CKRecordZone.ID(zoneName: "HouseholdZone-\(household.id)", ownerName: CKCurrentUserDefaultName)
let zone = CKRecordZone(zoneID: zoneID)
// AWAIT THIS FULLY
try await privateDatabase.modifyRecordZones(saving: [zone], deleting: [])

// 2. Prepare Root Record
let recordID = CKRecord.ID(recordName: household.id.uuidString, zoneID: zoneID)
let householdRecord = CKRecord(recordType: "Household", recordID: recordID)
// ... populate record ...

// 3. Prepare Share
let share = CKShare(rootRecord: householdRecord)
share[CKShare.SystemFieldKey.title] = household.name as CKRecordValue
share.publicPermission = .none

// 4. Atomic Save
let operation = CKModifyRecordsOperation(recordsToSave: [householdRecord, share], recordIDsToDelete: nil)
// ... run operation ...
```

### Step 2: Implement Universal Link generation
Create an `InviteLinkManager` that converts CloudKit URL to Universal Link and vice versa:
```swift
enum InviteLinkManager {
    static func createUniversalLink(from shareURL: URL) -> URL {
        var components = URLComponents(string: "https://housepulse.app/invite")!
        let encodedShareURL = shareURL.absoluteString.addingPercentEncoding(withAllowedCharacters: .urlQueryAllowed)
        components.queryItems = [URLQueryItem(name: "ckurl", value: encodedShareURL)]
        return components.url!
    }
}
```
*Pass this generated Universal Link into your QR Code generator.*

### Step 3: Share Interception & UI Flow
In your root SwiftUI view, intercept the URL:
```swift
.onOpenURL { url in
    Task {
        do {
            guard url.path == "/invite",
                  let components = URLComponents(url: url, resolvingAgainstBaseURL: true),
                  let ckUrlString = components.queryItems?.first(where: { $0.name == "ckurl" })?.value?.removingPercentEncoding,
                  let shareURL = URL(string: ckUrlString) else { return }

            // 1. Store cautiously in case auth fails
            UserDefaults.standard.set(shareURL.absoluteString, forKey: "PendingInviteURL")

            // 2. Fetch Metadata
            let metadata = try await container.shareMetadata(for: shareURL)

            // 3. Show Custom UI based on metadata
            appState.pendingInviteMetadata = metadata

        } catch CKError.notAuthenticated {
            appState.showiCloudSignInPrompt = true
        } catch {
            print("Failed to fetch share: \(error)")
        }
    }
}
```

### Step 4: Resume on Authentication
When the user returns from Settings after signing in to iCloud:
```swift
func checkPendingInvites() async {
    guard let urlString = UserDefaults.standard.string(forKey: "PendingInviteURL"),
          let shareURL = URL(string: urlString) else { return }

    if try? await container.accountStatus() == .available {
         // resume fetching metadata and accepting
         UserDefaults.standard.removeObject(forKey: "PendingInviteURL")
    }
}
```
